# 后端验证记录

在 Windows、Python 3.12、FastAPI 0.129.2 和实际 PostgreSQL 16.15 上执行。每个数据库集成测试迁移独立的临时 schema，并在测试结束后删除该 schema。文件操作在独立临时目录内执行。

- 运行 `python -m pytest -q` 后，26 个测试、10 个子测试通过。Starlette 测试客户端在当前 AnyIO 版本上发出一条弃用警告。
- Alembic 在实际 PostgreSQL 上完成首次迁移、模型与数据库结构比较、降级和重新迁移。比较结果无新增差异。
- `python -m pip wheel . --no-deps --no-build-isolation` 成功构建后端 wheel。
- 独立 Uvicorn 和 Worker 进程通过回环 HTTP 与真实 PostgreSQL 完成扫描、搜索、审批及实际文件移动。Worker 使用数据库配置启动。

覆盖范围包括授权目录和 Windows 路径校验、真实 junction、硬链接、删除共享锁、同大小同时间戳内容篡改、预检后出现同名目标的竞争、同卷移动和嵌套目录创建。数据库测试覆盖正文搜索及不同 NTFS 拼写的索引、PDF 和 DOCX 引用位置、无文本 PDF 状态、会话任务恢复、计划与作业关联、修订时保持源文件版本绑定、管理员审批绑定、重复执行、取消、撤销和两种准备日志中断场景。Worker 在移动前校验证据版本，支持同作业较早完成的证据文件移动。

设置 `FILEMATE_TEST_DATABASE_URL` 为可创建临时 schema 的专用 PostgreSQL 测试库后，从仓库根目录运行 `python -m pytest -q`。Windows 沙箱如果限制系统临时目录的父级句柄，将 `TEMP` 和 `TMP` 指向工作区中的专用临时目录。测试库 URL 未配置时，数据库用例会跳过。

执行器根据审批中的目标路径创建缺失的父目录。撤销是独立审批的新计划，移动成功的普通文件可以反向移动，已创建的目录可能保留。已存在的目标和仅大小写变化造成的同名目标会被拦截。读取摘录时先核验文件的当前版本。增量扫描只重新提取已变化文档的文本。摘要和搜索使用上次扫描的索引。文档提取最多处理 30 MiB 文件，超出文本或页数上限的提取结果会标记为截断。
